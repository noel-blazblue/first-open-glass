## 页面结构

每个示例页面尽量保持一致的阅读顺序：

- 示例说明：这个示例覆盖什么业务场景。
- 使用位置：从 Demo 哪个页面或入口进入。
- 关键文件：需要重点阅读的源码文件。
- 流程说明：按调用顺序说明核心链路。
- 相关 API：跳转到对应 API 参考章节。
- 接入注意：列出容易踩坑或需要结合业务改造的点。

## 后续补充原则

新增 Demo 能力时，优先补充到 [代码示例总览](../downloads/samples.md)，再为具体页面补齐入口、核心文件、流程说明和相关 API。这样开发者可以先从场景定位示例，再回到源码和 API 参考确认实现细节。
